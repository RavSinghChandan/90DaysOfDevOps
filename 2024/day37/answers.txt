Day 37 Task: Kubernetes Important Interview Questions
1. What is Kubernetes and why it is important?
Kubernetes is an open-source container orchestration platform that automates the deployment, scaling, and management of containerized applications. It ensures high availability, fault tolerance, and efficient resource utilization, making it essential for modern DevOps and cloud-native environments.

2. What is the difference between Docker Swarm and Kubernetes?
Feature	Docker Swarm	Kubernetes
Setup	Simpler and faster	Complex but feature-rich
Scalability	Limited	Highly scalable
Networking	Basic load balancing	Advanced networking
Features	Lacks rich features	Supports auto-scaling, rolling updates
Community	Smaller	Larger and more active
3. How does Kubernetes handle network communication between containers?
Kubernetes uses a flat network model where each Pod gets its own IP address. Pods can communicate with each other without NAT, and services enable communication through DNS or Cluster IP. CNI plugins (like Calico or Flannel) handle network policies and routing.

4. How does Kubernetes handle scaling of applications?
Kubernetes supports horizontal and vertical scaling:

Horizontal Scaling: Increases or decreases the number of Pods using the Horizontal Pod Autoscaler.
Vertical Scaling: Adjusts resource limits (CPU/memory) of Pods. Scaling can be manual or automated based on metrics like CPU, memory usage, or custom metrics.
5. What is a Kubernetes Deployment and how does it differ from a ReplicaSet?
Deployment: Manages the desired state of your application, supports updates, rollbacks, and scaling.
ReplicaSet: Ensures a specified number of Pod replicas are running. A Deployment internally manages a ReplicaSet.
6. Can you explain the concept of rolling updates in Kubernetes?
Rolling updates in Kubernetes ensure zero-downtime application updates. It gradually replaces old Pods with new ones, ensuring some Pods are always running. This is managed via the Deployment object.

7. How does Kubernetes handle network security and access control?
Network Policies: Define allowed communication between Pods and external entities.
RBAC (Role-Based Access Control): Manages access permissions for users and services.
Secrets and ConfigMaps: Securely store and manage sensitive data.
8. Can you give an example of how Kubernetes can be used to deploy a highly available application?
Deploy a multi-replica Deployment managed by a Service with a LoadBalancer. Use multiple nodes to avoid single points of failure. Combine with a distributed database (like etcd or Cassandra) for backend high availability.

9. What is a namespace in Kubernetes? Which namespace does any Pod take if we don't specify any?
A namespace is a logical isolation within a Kubernetes cluster, used to organize and manage resources. By default, Pods are created in the default namespace if no namespace is specified.

10. How does Ingress help in Kubernetes?
Ingress provides HTTP and HTTPS routing to services based on domain names and paths. It supports load balancing, SSL termination, and name-based virtual hosting, enabling external access to applications.

11. Explain different types of services in Kubernetes?
ClusterIP: Default service type; internal communication within the cluster.
NodePort: Exposes a service on a static port on each node.
LoadBalancer: Provides an external IP using a cloud provider's load balancer.
ExternalName: Maps a service to an external DNS name.
12. Can you explain the concept of self-healing in Kubernetes and give examples of how it works?
Kubernetes automatically replaces failed Pods and reschedules them on healthy nodes. For example:

Restarting Containers: Handled by livenessProbe and readinessProbe.
Replacing Pods: ReplicaSets ensure the desired Pod count.
Rescheduling: Failed Pods are rescheduled on available nodes.
13. How does Kubernetes handle storage management for containers?
Kubernetes uses Persistent Volumes (PVs) and Persistent Volume Claims (PVCs). Storage backends like AWS EBS, NFS, or Ceph provide data persistence. Dynamic provisioning allows automatic PV creation based on claims.

14. How does the NodePort service work?
NodePort exposes a service on a specific port on all cluster nodes. It allows external access to applications by routing requests to the underlying Pods.

15. What is a multinode cluster and single-node cluster in Kubernetes?
Single-node Cluster: Control plane and worker nodes run on the same machine (e.g., Minikube).
Multinode Cluster: Separate machines for control plane and worker nodes, offering higher availability and scalability.
16. Difference between create and apply in Kubernetes?
Create: Used to create a new resource from a manifest (kubectl create -f).
Apply: Used to create or update resources while maintaining declarative configuration (kubectl apply -f).
